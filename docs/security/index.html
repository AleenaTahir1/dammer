Security and permissions

Built so it can’t spy on you.

Auto-refresh extensions have a history of being used for ad injection and tracking. Dammer is designed so that there is very little it could do, even with a bug.

What the design rules out

  • No network access. The content security policy sets connect-src 'none', so the browser blocks every outgoing connection from the extension. An automated check fails the build if fetch, XMLHttpRequest, WebSocket, eval or new Function appear in the code.
  • No remote code. Every script ships inside the package. Nothing is downloaded after install.
  • No access to page content. There are no content scripts, no host permissions and no scripting permission.
  • No messages from outside. Web pages and other extensions cannot talk to Dammer, and its background script rejects any message that does not come from its own popup.
  • Page data is treated as text. Tab titles and addresses come from web pages, so they are only ever inserted as plain text.
  • Stored addresses are trimmed. Anything after a question mark or hash is removed before an address is saved.
  • No dependencies. There are no third-party packages and no build step that could be tampered with.

Permissions, and why each is needed

PermissionChrome's warningWhat Dammer uses it for
tabs"Read your browsing history"Reading the title and address of open tabs, to list them in the tab picker and to notice when the chosen tab has left its site.
alarmsNoneWaking the background script when a refresh or the auto-stop is due.
storageNoneSaving your settings and chosen tab on your computer.
idleNoneLearning whether the computer was used recently, so a tab you are looking at is not reloaded and the timer can stop when you step away.

Chrome words the tabs permission as "Read your browsing history" because tab addresses reveal which sites are open. Dammer reads them only while the popup is open or a refresh is due, keeps at most one trimmed address (the tab you chose), and has no way to send anything anywhere.

Not requestedWhat that rules out

Check it yourself

You do not have to take any of this on trust.

  • Read the code. The extension is about 2,300 lines of plain HTML, CSS and JavaScript in the extension folder.
  • Rebuild the download. Release zips are built by a public GitHub Actions workflow from the tagged commit. Run npm run build and compare.
  • Run the tests. npm test drives the real extension in a real copy of Chrome and runs 58 checks, including that reloads happen exactly once and that the timer survives the background script being stopped.
  • Watch the network. Open the popup, right-click it, choose Inspect and look at the Network tab. It stays empty.

Reporting a security problem

Please report it privately, not in a public issue. On the repository's Security tab, click Report a vulnerability and describe what you found and how to reproduce it. You can expect an acknowledgement within a week. Only the latest release receives fixes.
